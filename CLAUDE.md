## Что это
- Бот для мобильной игры *Hero Wars* на Python. Проходит **одну локацию — титановое Подземелье** (Dungeon), не всю игру.
- Игра — на Android-телефоне, подключённом к ПК (Windows) по USB. Экран телефона — в окне scrcpy с заголовком
  `HeroWarsBot_Arena`. Бот снимает это окно (`mss`), ищет картинки-шаблоны (OpenCV) и жмёт через ADB.
- Репозиторий — `DungeonBot`; окно программы называется «Hero Wars: Knowledge Engine Bot», файл — `HeroWarsBot.exe`,
  окно игры — `HeroWarsBot_Arena` (их при переезде не переименовывали). Версия — `config.APP_VERSION`.
- **Запустить бота в облаке нельзя:** нет телефона, игры и scrcpy. Проверяет пользователь у себя.

## Как пользователь запускает
- **Игроки:** архив из Releases → распаковать в новую пустую папку → `HeroWarsBot.exe`. Обновление — новая папка и перенос
  `profile.yml` и `bot_data/`.
- **Автор из исходников:** Python 3.11+ (numpy 2.5 на 3.10 не ставится), `start.bat` (создаёт `venv`, ставит `requirements.txt`,
  запускает `python gui.py`). Запускать **из папки проекта**: пути относительные. Поменялся `requirements.txt` —
  `venv\Scripts\activate`, `pip install -r requirements.txt` (`start.bat` ставит библиотеки только в первый раз).
- Один раз: scrcpy (с adb) в `PATH`; на телефоне «Отладка по USB» **и** «Отладка по USB (настройки безопасности)» — без второго
  нажатия не доходят.
- В окне: «Подключить телефон» → в игре встать в коридоре подземелья → «Начать фарм».
- Бот без окна (отладка): `scrcpy --window-title HeroWarsBot_Arena --stay-awake`, во втором cmd `venv\Scripts\activate`,
  `set HEROWARS_LANG=RU`, `python -X utf8 -u main.py`; ответы на SOS — печатать в консоль (`IGNORE`, `STOP`, `MANUAL`,
  `ROLLBACK:hyperion,sigurd,...`, `CONFIRM`). Окно scrcpy должно быть около 1606×748.
- **Сборка `.exe`:** `build_exe.bat` (нужны `venv` и свежий `assets_db.py` — `python pack_assets.py`, оба файла только у автора).
  Результат — `dist\HeroWarsBot\HeroWarsBot.exe` и рядом только `_internal`. PyInstaller: `--onedir --windowed --name HeroWarsBot
  --hidden-import main --hidden-import assets_db --hidden-import PIL._tkinter_finder --add-data guide;guide
  --add-data ui/icons;ui/icons gui.py` (папку `assets/` в `.exe` не кладём: все картинки, и титаны для окна, — в `assets_db.py`;
  папки `assets/` у автора может не быть). `profile.yml` и `bot_data` из `dist\HeroWarsBot` на время сборки уходят
  в `build_keep\` и возвращаются. В `.exe`: шаблоны бота — из `assets_db.py`, руководство — `_internal/guide`
  (`ui/guide_renderer.guide_dir`), `profile.yml` и `bot_data/` — рядом с `.exe`. Библиотеки сборки — `requirements-build.txt`.
- **Релиз:** поднять `config.APP_VERSION`, собрать, заархивировать `dist\HeroWarsBot`, GitHub → Releases → новый релиз
  с тегом версии. Кнопка «Проверить обновления» открывает страницу релизов (`config.GITHUB_REPO`).
- Антивирус может ругаться на `.exe` (ложное срабатывание PyInstaller) — добавить папку в исключения.

## Как устроено: два процесса
1. **`gui.py`** — окно программы (`ui/app.py`, CustomTkinter + свои лёгкие виджеты). «Подключить телефон» запускает scrcpy
   (`environment.py`), «Начать фарм» подгоняет окно scrcpy под 1606×748 и запускает бота: `python -X utf8 -u main.py`
   (в `.exe` — `<exe> --bot-mode`, `ui/bot_link.bot_command`). Язык игры — переменная `HEROWARS_LANG`.
2. **`main.py`** — бот, машина состояний. **Запускает бота прямо при импорте** — не импортируй его. Всё, что он печатает,
   окно показывает в журнале. Каждая строка начинается со времени (`14:03:21.457 [НАВИГАЦИЯ] ...`), копия лога —
   `bot_data/logs/bot_log_<дата>_<время>.txt` (`session_log.py`).
- Замеры (`session_log.py`): после комнаты `[ВРЕМЯ] Комната N (стихия): коридор | сборка | бой | результат | всего`
  (и `timings_*.csv`), при остановке блок `[ИТОГ]` (память, поиск окна, паузы реакции, нажатия adb). Новые замеры —
  через `session_log` (`count`, `excluded`, `ROOM_TIMER.begin`), не новым `print`.

## Связь окна и бота — не ломать
- **Бот → окно** (окно ищет подстроку, `ui/bot_link.py:parse_line`; время в начале строки допустимо, маркер и JSON — нет):
  - `[SOS_TRIGGER]` + JSON: `{"titans": {...}, "is_manual": ...}` — плохой бой, окно «Требуется вмешательство»;
    `{"type": "NO_VALID_TEAM", ...}` — нет подходящего пака; `TEST_SUCCESS:{...}` — проверяемый пак выиграл.
    Перед ним бот пишет `bot_data/sos_info.json` (комната, враги, причина, пак — для Telegram).
  - `[SOS_CLOSE]` — бот решил сам, окно закрывает SOS-окна и опрос Telegram, старые ответы не шлёт (`sos_epoch`).
  - `[ПАУЗА ОТЛАДКИ]` — включает кнопку «Продолжить».
- **Окно → бот:** одна строка в stdin: `IGNORE`, `MANUAL`, `STOP`, `ROLLBACK:титан1,титан2,...`, `ROLLBACK_TG:...`, `CONFIRM`,
  `NEW_PACK:...`. Какое окно что принимает — `sos_answers.ALLOWED`; чужая команда → `[ЛОГИКА] Непонятный ответ ...` и тот же
  `[SOS_TRIGGER]` ещё раз. Ответ, пришедший раньше вопроса, пропускается (`wait_for_input(since=...)`).
  `EXIT:причина` — остановиться в любой момент (поток `stdin_listener`, `exit_if_requested`), окно шлёт его, когда пропало окно
  scrcpy; не отозвался за 10 с — процесс останавливается. `STOP` из SOS-окон — бот сам пишет `[ИТОГ]` и шлёт итог в Telegram
  (не отозвался за 10 с, `bot_link.STOP_GRACE_S`, — окно добивает). «СТОП F10» убивает процесс сразу.
  Канал закрылся (окно упало) — бот доигрывает бой и останавливается (`main.py:output_gone`).
- **Мягкая пауза** — файл `pause.flag` в папке бота (создаёт окно; бот — при сбое отката, зависаниях). Пока он есть, бот ждёт
  в коридоре; начатую комнату (сборку, бой, ульту Ангуса) доигрывает.
- **Горячие клавиши:** окно — F9 пауза, F10 стоп (`ui/hotkeys.py`); бот — Ctrl+Q остановиться после боя, Ctrl+Shift+Q сразу
  (сначала запрет нажатий `vision.stop_taps`). Всё — только когда активно окно игры, окно программы или консоль (`win_focus.py`).
- **Бот работает, только пока активно окно игры** (`main.py:wait_for_focus`). Мини-бар поэтому никогда не становится
  активным окном (`WS_EX_NOACTIVATE`).

## Цикл комнаты (`main.py`)
`HALLWAY` → `ROOM_SELECTION` → `SET_TEAM` → `PREP_AUTO` / `PREP_SPECIAL_ANGUS` → `WAIT_FOR_OK` → `HALLWAY`.
1. **HALLWAY** (`navigation.py`): на одном снимке ищет флажок двери, «Атаковать», «Активировать». Дверь жмёт, когда флажок
   замер (3 снимка в одной точке ±3 px, не меньше 0,2 с, не дольше 3 с); окно не открылось за 2 с — промах, смотрит снова.
   Точка сохранения: «Активировать» → «Забрать» → ждёт флажок нового этажа (до 12 с). Лимит — может встать **перед** точкой.
2. **ROOM_SELECTION** (`combat.find_smart_door`): кнопки «Атаковать» и стихия двери по иконке (water/mix/earth/fire), лог
   `[НАВИГАЦИЯ] Двери (слева направо): ...`. Порядок — `door_order` (по умолчанию вода → микс → земля → огонь), запреты skip,
   при «Бот решает сам» — по здоровью (`main.door_hints`). Разбирает снимок, где кнопки замерли (`click_logic.spots_still`),
   распознаёт врагов (`analyzer.scan_enemy_team`).
3. **SET_TEAM:** читает слоты и полоски ХП/энергии под иконками (`main.read_team_screen` → `team_manager.scan_slots`),
   цифры экрана заменяют память **до** выбора пака (`[СОСТОЯНИЕ] Перед боем ...`). Пак — `engine.battle_decision`, дальше
   поправки тактики (пак отхила, запасной, опасность для раненых). Сборка — `team_manager.verify_and_set_team`: совпало —
   ничего не жмёт; иначе лишних убирает **слева направо** (слоты прижаты вправо), ставит нужных из сетки, после свайпа ждёт
   остановки сетки, состав принимает по двум одинаковым снимкам. Не собралось за 3 попытки — `team_fail_…png`, Telegram,
   мягкая пауза. Уже стоявший пак (`LAST_USED_TEAMS`) пропускается, только если все его титаны видны.
4. **PREP_AUTO** — «Авто». **PREP_SPECIAL_ANGUS** — только при `angus_manual_control`: «В бой», автобой на 1,8 с для ульты,
   выключить. Бой не начался 10 с — снова в `SET_TEAM` (до 3 раз), потом ждёт связь 30 с, 1, 2, 4, 8 мин, потом
   `start_fail_…png`, Telegram, мягкая пауза (`click_logic.after_failed_battle_start`).
5. **WAIT_FOR_OK:** «ОК» окна результата; читать начинает через 1,2 с после появления (`result_scan.RESULT_ANIMATION_S`),
   нужны 3 одинаковых снимка полосок подряд, лог `[АНАЛИЗАТОР] Окно результата ...` и `---> ТИТАН: ХП ...`. Титан не найден —
   пересканирует до 3 раз; не нашёлся — SOS «Не удалось прочитать окно результата». Оценка — `battle_verdict.evaluate_battle`.
   - Хорошо: бой в историю и статистику, `[СТАТИСТИКА] Комнат: N`, «ОК» (`RESULT_DONE` — второй раз не считать).
   - Плохо: `[SOS] Причина: ...` и `[SOS_TRIGGER]` (или решение без вас, см. тактику).
   - «Пройти руками» (`MANUAL`): бот ничего не жмёт и ждёт коридор 2 с подряд (`main.play_manually`, `stuck_guard.ManualPlay`).
   - Откат: `main.run_rollback` → `combat.execute_rollback` → `rollback_logic.retreat_from_battle`: «Ещё раз» → кнопка паузы
     (до 60 с) → пауза **один раз** → «Отступить» → коридор (15 с). Нет связи — ждёт игру до 15 мин. Не удалось —
     `rollback_fail_…png`, Telegram, мягкая пауза (`main.handle_rollback_failure`). Удачный новый пак — правило
     (`rules_engine.learn_new_rule`: «против этих врагов» + условие проигравшего правила, без дублей).
   - `debug_mode` в `config.py` — после удачного боя `bot_data/debug/result_debug_…png` (что бот намерил) и пауза отладки.
6. Перед дверью — лимиты сессии (`main.get_stop_reason`, `session_limits.py`).

## Как бот выбирает пак (`rules_engine.py`)
- Файлы `bot_data/rules/<стихия>.yml` (earth, fire, mix, water): `default_team` и список `rules`. Пишут «Мастер правил» и бот.
  Папка создаётся сама; в репозитории правил нет. Читаются при запуске; запоминая правило, бот перечитывает эту стихию.
- Порядок: `action: skip` (чёрный список, запрет дверей) → спасение (`titan_hp_below`, `titan_energy_below`) → анти-паки
  (`enemies_contain`) → базовый пак. Внутри группы — сверху вниз.
- Особое: пак `[STOP]` — спросить; `require_fought`; `allowed_delta` — свой допуск; `special_ult: angus` — только при
  переключателе Ангуса; `enabled: false` — правило выключено, бот его пропускает и не трогает при обучении.
- Испорченный YAML при запуске — `[ПРАВИЛА] Бот не запущен. Файл … испорчен (строка N)` и выход; во время фарма такой файл
  бот не перезаписывает. Устаревшие правила `rules_engine.OBSOLETE_RULES` удаляются при запуске.

## Бот решает сам (`tactics.py`, переключатель «Бот решает сам» = `auto_rollback`)
- Настройки — `tactics.Settings` из `profile.yml`: `critical_hp` (порог паники, 40), `max_hp_delta` (допуск потерь, 30),
  `group_loss_titans`/`group_loss_percent` (3 титана по 40%), `titan_critical_hp` (личные пороги), `auto_rollback_tries`
  (2, от 1 до 3), `backup_teams`, `door_order`, `sos_timeout_minutes` (10, 0 — ждать всегда), `heal_below_hp` (60, 0 — не лечить),
  `heal_remove_order`, `reset_hour` (5), `angus_manual_control`. Всё задаётся в окне («Мастер правил»).
- Плохой бой: кто-то умер или не найден; ХП ниже порога паники; потеря больше допуска; общие потери; правило отхила
  сработало из-за этого боя.
- Плохой бой → откат и запасной пак (`choose_backup`: ваши запасные → паки правил против этих врагов → победившие этих врагов →
  остальные → история; без проигравших, запрещённых, ниже паники). Не сам, если бой ручной, окно не прочиталось или пак выбрали вы.
  Запасной справился — правило запоминается, **кроме** случая «враги ни при чём» (`battle_verdict.full_hp_reason`).
- Перед боем: пак проигрывает этим врагам (`HISTORY.lost_to`) или опасен раненому по прогнозу (`wounded_at_risk`: ХП минус
  средняя потеря за 5 боёв, с учётом энергии ±25%) — сразу запасной (разовая помощь, без правила).
- **Пак отхила** (`heal_plan`, только смешанная, вместо базового): раненый ниже `heal_below_hp`, но выше паники; лечим по одному,
  основных раньше запасных; встаёт вместо первого из «кого убирать»; лекарь — из `titans.py` (`healer`); не встал в слот —
  этого титана до конца запуска не лечим.
- Дверь по здоровью, «золотые правила» при запуске (5+ боёв, 80%+ побед против этого состава → `source: golden`).
- Молчание на SOS `sos_timeout_minutes` → `[ТАКТИКА] Ответа нет N мин. Решаю сам.`, решение `decide_without_you`, `[SOS_CLOSE]`.
- История боёв — `bot_data/logs/*.jsonl` (`BattleHistory`; поражение пака — только если виноваты враги, по нынешним порогам).
- Память ХП/энергии — `titan_state.TitanMemory` в `bot_data/titan_state.json` в пределах игрового дня.

## Защита от зависаний, связь, блокировка ПК
- Пределы (`stuck_guard.StateClock`): экран выбора команды не пришёл за 30 с, окно результата — за 3 мин → `[СТОРОЖ] Зависание`,
  `stuck_…png`, умный старт. Сторож: 5 мин без комнаты → Telegram и умный старт, третья тревога подряд → мягкая пауза.
- Ожидание человека (SOS, пауза, ручной бой, нет фокуса) сторож не считает — новые ожидания тоже через `main.user_waited()`.
- Снимки — только `vision.grab_frame`: при Win+L ждёт разблокировки (`[ЭКРАН] Не удаётся сделать снимок экрана ...`).
- Telegram-тревоги — в фоне с повторами при обрыве связи (30 с, 1, 2, 5, 10 мин, `send_alert_in_background`).

## Telegram (`telegram_agent.py`, `telegram_report.py`, `telegram_i18n.py`)
- Сообщения только при проблемах + итог сессии при любой остановке, кроме «СТОП F10». SOS шлёт окно (`ui/sos_telegram.py`).
- Тексты — `telegram_report.py` (HTML, цветные кнопки), слова — `telegram_i18n.py` на 13 языках (язык окна). Лог бота — по-русски.
- Запросы ждут не дольше `telegram_agent.TIMEOUT`; токен и chat_id — только из `profile.yml`; в тексте ошибок токен — `***`.

## Зрение и нажатия (`vision.py`)
- Калибровка: область игры без рамок, масштаб от высоты 720 (эталон окна 1606×748, масштаб ~0,978).
- Шаблон: `assets/<ЯЗЫК>/имя.png`, если есть, иначе `assets/имя.png`; если есть `assets_db.py` — **берётся из него**
  (тогда после замены картинки его надо пересобрать или удалить). `assets/UK/` — копии английских кнопок (так в игре).
- Поиск — `best_match`/`match_scores` (сначала уменьшенный снимок), только в частях экрана `vision.AREAS`; несколько картинок
  на одном снимке — `find_many`/`find_on_frame`. Не вызывай `cv2.matchTemplate` по всему снимку и `sct.grab` напрямую.
- Пороги: обычно 0,75–0,8; титаны в слотах 0,88; враги 0,72; иконки окна результата 0,62. У «Ещё раз» ищется только надпись
  (`TEMPLATE_CROP`) — целиком она путалась с «Инфо». Крестик закрытия окон бот не жмёт (в коридоре это выход из подземелья).
- Нажатия — `click_human` через одно соединение `adb shell` (`adb_shell.AdbShell`); точка случайная (20% от краёв не трогает);
  пауза реакции 0,3–0,8 с от **появления** кнопки (`seen_at`) и не чаще 2 нажатий в секунду (`click_logic.TapPacer`).
  Повтор — только если через 4 с после доставки экран не отреагировал (`RetryPolicy`, до 8 с), пропажа кнопки — по второму
  снимку через 0,25 с. Разрешение телефона не узнали за 10 с — бот не жмёт, мягкая пауза.
- Полоски ХП/энергии: зелёная и под ней жёлтая; пустая часть почти чёрная; длину полоски бот меряет сам.

## Лимиты, этажи, титанит
- Цели: время, комнаты, этажи, титанит (по умолчанию 120, `config.LIMITS`). Этаж считается по точке сохранения
  (`session_limits.FLOORS`). Лимит по этажам — стоп сразу после награды. Остальные — `[ЛИМИТ] ... Доигрываю этаж` и стоп
  **перед** точкой сохранения, «Активировать» не жмёт (`stop_at_checkpoint`); точка не нашлась за 6 комнат — стоп как есть.
- Титанит считается, не читается: 6 за комнату, 12 с «x2».

## Титаны (`titans.py`)
- Одна строка на титана: стихия (`elarite` — только смешанная), `place` (позиция 1–5 и очередь), `elarite=True`, `healer`
  (номер, 1 — сильнее всех), `enemy=True` (бывает врагом, нужна `enemy_<имя>.png`), имена на языках (`RU=`, `EN=`, …).
  Отсюда берут окно (`ui/theme.py`), `i18n.py` (`titan_<имя>`), `tactics.HEALERS`, `config.ENEMY_TITANS`, Telegram.
  Порядок строк не переставлять (по нему бот ищет врагов). `team_manager.GAME_ORDER` — новый титан в конец.
- Новый титан: строка в `titans.py` + у пользователя картинки `assets/<имя>.png` (слот), `assets/res_<имя>.png` (окно
  результата), `assets/icons/<имя>.png` (окно, без неё — две буквы), враг — `assets/enemy_<имя>.png`; для `.exe` — пересобрать
  `assets_db.py`. Титан только с картинками без строки тоже находится (`titans.unknown`), в окне — «Новые титаны» серым.

## Окно программы (`ui/`) — правила, на которых уже обжигались
- Окно не должно зависать и обязано закрываться крестиком без диспетчера задач. В обработчиках наведения — только цвета
  и только при изменении; никаких `update()`, `wait_window`, `wait_visibility` в обработчиках; долгая работа — в поток,
  в окно — через очередь `App.events` (окно разбирает раз в 100 мс) и `after`. Сторож — `ui/freeze_guard.py`
  (`bot_data/debug/ui_freeze_*.txt` при 5 с без ответа, `ui_lag_*.txt` — задержки больше 0,5 с).
- **Внутри окон нет элементов CustomTkinter:** `ui/light.py` (`Frame`, `Box`, `Label`, `Button`, `Entry`, `Textbox`, `Scrollbar`,
  `ScrollArea`, `ScrollableFrame`, `ProgressBar`, `SegmentedButton`, `CheckBox` — аргументы как у CustomTkinter) или простой Tk
  (`widgets.PlainLabel`, `plain_icon`, `TitanTile`, `PlainButton`, `RoundedBackdrop`). CustomTkinter — только окна
  (`App` = `ctk.CTk`, `widgets.AppWindow`) и картинки `CTkImage`. Размеры лёгких элементов — в пикселях макета
  (`light.Scaled`, `cpx`), у простого Tk — `px()`.
- Все окна — `widgets.AppWindow`, показывать через `widgets.present_window`; модальность — только `widgets.hold_grab` (своих
  `grab_set` нет). Окна без рамки Windows: крестик `widgets.close_button` зовёт то же, что `WM_DELETE_WINDOW`.
- Выпадающие списки и меню правой кнопки — `widgets.PopupMenu`, не `tk.Menu` (у меню Windows белая рамка).
- В Windows у окна без заголовка **нет `wm geometry`**: место и размер — `win_frame.set_window_rect`; перетаскивание —
  `win_frame.drag_window` (**только `PostMessage`, никогда `SendMessage`** — Python 3.13 аварийно закрывается); **без `-alpha`**
  (`light.NoAlpha`). Всплывающее окно — размер по содержимому, задаётся только место `"+x+y"`; переставлять — после
  `<Configure>` через `after_idle`.
- Видна одна страница, остальные запаркованы (`App._park_page`), новая — под заслонкой; обновлять при показе —
  `refresh_data()`, не `<Map>`. События окна о себе — `light.OwnEvents`.
- Не называй методы в подклассах CustomTkinter `_draw`, `_image`, `_text`, `_hover`, `_on_enter`, `_on_leave`; у `light.Box`
  заняты `_box_*` и `_after_box_draw`. Контейнерам `light.Frame` давай `width=10, height=10` (иначе 200 px); линии 1 px —
  `tk.Frame(bg=C["border"])`. Длинные списки строятся частями, правка меняет только свои строки.
- Цвета (hex) — только в `ui/theme.py`; иконки — `ui/icons` (`icon(имя, цвет, размер)`); надписи — `i18n.py` **на всех 13 языках**
  (`i18n.LANGUAGES`); эмодзи из старых надписей убирает `theme.plain_text`. Титаны в окне — внутренними именами (`araji`),
  показываются в порядке игры (`theme.screen_order`), в файлах порядок прежний.
- Все настройки — в окне; пользователя не проси править файлы руками. «Сохранить настройки» пишет только поменянное
  (`ui/rules_store.py`, `ui/rules_list.py`): пользователь просит писать файлы как можно реже.
- Новая библиотека — только с согласия пользователя, сразу в `requirements.txt` с версией; в отчёте — как поставить.

## Руководство (`guide/`, страница «Руководство»)
- Текст — `guide/<код языка>.md` (нет — `en.md`, потом `ru.md`). Пишется только `ru.md`, остальные — переводчиком.
- Разметка (разбор — `ui/guide_renderer.py`): `#` заголовок (один); `##` раздел (номер сам, пункт оглавления); абзацы через
  пустую строку; `**жирный**`; кнопки — в «ёлочках» слово в слово как в `i18n.py`; `` `код` ``; `- пункт`, `- :иконка: пункт`
  (имя из `ui/icons`); `1. **Шаг** — текст` (карточки по 2 в ряд); `> [!tip]`, `> [!note]`, `> [!warning]`, `> [!done]`
  (плашки; `[!tip]` с отступом под шагом — внутрь карточки); `![Подпись](images/имя.png)`; `[текст](#N)` — к разделу N; `---`.
- Картинки: путь в тексте без языка, файл — `guide/images/<язык>/имя.png` → `guide/images/имя.png` → `en/` → `ru/`
  (`guide_renderer.find_image`). Какие нужны — `guide_images.bat`.
- Перевод — `translate_guide.bat` (Gemini, ключи в `gemini_keys.txt` рядом, он в `.gitignore`; модель `translate_guide.MODEL`).
  Переводит только изменённые разделы (`guide/translate_state.json`), каждый ответ проверяет (`check`). Поменял разметку — научи
  переводчик (`skeleton`/`layout`). Строки журнала `[ТЕГ] …` в руководстве остаются по-русски. Переведено пока: `en`.

## Решения пользователя (почему так)
- Двери: вода → микс → земля → огонь — так играет ~90% игроков: в воде 2 лекаря, микс — для отхила, в земле слабый лекарь
  (Авалон), в огне лекарей нет. Порядок можно поменять в окне.
- Лечат: Гиперион (сильнее всех), Ияри (и заряжает энергию), слабо — Авалон, Сигурд, Солярис, Паллант (артефакт), Метида.
  Огонь без лекарей — после него обычно кого-то лечат в смешанной. Лечение — по одному титану; не доводить до двух раненых.
- Энергия важна: Араджи с 60–80% энергии в огне теряет мало; Сигурд с малой энергией в смешанной — плохо.
- Умершие титаны недоступны до конца игрового дня. Ручной бой после «Ещё раз» не начинается автобоем.
- Скорость: «чем быстрее, тем лучше, но без перегибов» — 0,3–0,8 с реакции, не больше 2 нажатий в секунду, случайная точка.
- Лимит: доиграть этаж и встать перед точкой сохранения (награду не брать); цель «Этажи» — сразу после награды.
- Титанит: 6 за комнату, 12 с «x2» (с 3-го этажа), с экрана не читаем.
- Telegram: только проблемы (враги списком, по-человечески, скриншот) и итог сессии.
- Ручная ульта Ангуса по умолчанию выключена — земля идёт автобоем.
- «Аналитики» в окне нет: золотые правила бот создаёт сам при «Бот решает сам».
- Новый игрок начинает с пустыми паками (правил по умолчанию нет); `bot_data/rules/` создаётся сам.
- Пороги у каждого игрока свои — универсальные значения по умолчанию, всё настраивается в окне.

## Частые поломки и что делать
- **Бот не находит кнопку / жмёт не туда** (игра поменяла картинку, другой язык): попроси строки лога вокруг места
  (поиск по `[НАВИГАЦИЯ]`, `[КОМАНДА]`, `[СТОРОЖ]`) и скриншот экрана игры. Новая картинка — пользователь вырезает и кладёт
  в `assets/<ЯЗЫК>/имя.png` (или `assets/имя.png`), если есть `assets_db.py` — пересобирает (`python pack_assets.py`)
  или удаляет; для `.exe` — пересборка. Порог и часть экрана (`vision.AREAS`) менять только с согласия и проверив на скриншоте.
- **Не узнаёт титана в слоте или сетке:** картинка `assets/<имя>.png`, порог 0,88, `team_manager.best_per_spot`;
  попроси `team_fail_…png` из `bot_data/debug/`.
- **Окно результата не читается:** `result_unreadable_…png`; включить `debug_mode` в `config.py` → `result_debug_…png`.
- **Зависание бота:** `[СТОРОЖ]` в логе и `stuck_…png`. **Обрыв связи:** `[ОТКАТ]`, `[СЕТЬ]`, `rollback_wait_…png`.
- **Окно программы зависло:** `bot_data/debug/ui_freeze_*.txt` (где застрял код), `ui_lag_*.txt`.
- **Нажатия не доходят:** «Отладка по USB (настройки безопасности)»; строки `[ADB] ...`.
- **Бот сам остановился:** причина — в блоке `[ИТОГ]` и в итоге в Telegram.
- **Telegram молчит:** кнопка «Проверить Telegram» в окне; строки `[TELEGRAM]`, повторы при обрыве.
- **Файл правил испорчен:** строка `[ПРАВИЛА] Бот не запущен ...` — открыть «Мастер правил» и сохранить заново.
- Где в логе комната: строки `[СТАТИСТИКА] Комнат: N`; несколько запусков в одном логе — счёт заново.

## Как проверять
- Тестов в репозитории нет (решение 01.11.2026). Минимум — `python -m py_compile <изменённые файлы>`.
- Логику без игры проверяй маленьким скриптом во временной папке (не коммить): в облаке
  `pip install pyyaml numpy opencv-python-headless`. Без OpenCV и Tk проверяются `click_logic`, `rollback_logic`, `stuck_guard`,
  `battle_verdict`, `tactics`, `titan_state`, `session_limits`, `sos_answers`, `titans`, `telegram_report`, `ui/bot_link`,
  `ui/*_data.py`, `ui/rules_store.py`. Ловушки: `main.py` нельзя импортировать (бот стартует); `pygetwindow` на Linux падает
  при импорте — заглушка `sys.modules["pygetwindow"] = types.ModuleType("pygetwindow")` до импорта `vision` и др.;
  `rules_engine` и `analytics` при импорте читают/чистят файлы в текущей папке — сначала перейди во временную папку;
  `data_paths._CHECKED` помнит проверенную папку. Распознавание без картинок `assets/` в облаке не проверить.
- Окно в облаке: `apt-get update && apt-get install -y python3-tk fonts-roboto xvfb`, `python3.12 -m pip install
  --break-system-packages customtkinter==6.0.0 pyyaml requests` и `--ignore-installed pillow==12.3.0`, запуск под
  `xvfb-run -a python3.12 ...`, снимок — `PIL.ImageGrab.grab`.
- Нужны старые тесты (крупная правка механики) — их можно взять из архивного репозитория во временную папку, не коммитить.
- Главная проверка — у пользователя в игре: в отчёте дай шаги и строки лога, на которые смотреть.

## Правила работы
1. Одна задача — одна сессия. Меняй только нужные файлы. Нашёл другое — скажи, но не чини без спроса.
